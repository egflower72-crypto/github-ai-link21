# 매일 설계 절차

파일 이름: `daily/YYYY-MM-DD_<저장소이름>.md` (날짜는 Asia/Seoul)

## 순서
1. 수집: GitHub 일간 트렌딩과 스타 상위에서 후보 3개를 뽑는다. `daily/`에 이미 있는 저장소는 뺀다.
2. 분류: 링크21 업무(AI 교육 운영, 수강생 모집·상담, 교안 제작, 수료·정산, 콘텐츠 발행)에 붙는 것 1개를 고른다. 붙는 것이 없으면 「오늘은 해당 없음」 한 줄과 후보 3개만 남기고 끝낸다.
3. 검증: 라이선스, 최신 릴리스, 최근 30일 커밋, 보안 권고(저장소 권고와 GitHub Advisory Database 둘 다)를 원문에서 확인한다. 확인 못 한 것은 「확인 불가」로 적는다.
4. 구조 파악: README, 디렉터리, 핵심 모듈, 데이터 모델을 읽고 동작 방식을 정리한다.
5. 설계: 아래 양식으로 1장.
6. 검수: 새 맥락의 검수자 1명이 「이걸 만들 가치가 없다」는 쪽에서 공격한다. 지적과 반영 여부를 설계서 끝에 붙인다.

## 설계서 양식
- 한 줄 결론: 만든다 / 보류 / 사용 불가
- 저장소: 주소, 라이선스, 스타, 최신 릴리스, 확인 시각
- 무엇을 하는 도구인가 (3줄)
- 링크21의 어떤 일을 줄이는가: 지금 방식 → 바뀐 방식, 주당 절약 시간 추정(추정임을 표시)
- 구조: 프론트 / 백엔드 / 데이터베이스(테이블과 주요 컬럼) / 외부 연동
- 가장 작은 완성판 범위: 화면 목록, API 목록, 만들지 않을 것
- 위험: 개인정보, 비용, 유지보수, 라이선스
- 구축 예상: 작업 단계와 완료 기준
- 검수 지적과 반영 여부
